# Spec-driven development

Esta pasta guarda o entendimento do domínio **depois** que o tema do hackathon
for anunciado. Antes disso, os arquivos são templates.

## Ordem de preenchimento

1. `domain.md`: problema, usuários, fluxos, regras e perguntas abertas.
2. `docs/requirements/functional.md`: o que o sistema deve fazer.
3. `docs/requirements/non-functional.md`: qualidade, segurança e restrições.
4. `docs/backlog/KANBAN.md`: stories pequenas e verificáveis.
5. `docs/tasks/<KEY>/plan.md`: plano da story escolhida.

## Regra

Nenhuma story de produto começa sem critério de aceite verificável e sem citar o
requisito relacionado. Se o tema mudar, atualize o domínio antes do código.
